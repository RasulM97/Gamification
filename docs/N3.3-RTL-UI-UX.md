# N3.3 — RTL UI/UX finalization

## Scope and baseline

Presentation only. N3/N3.1/N3.2 localization, all ten dictionaries, font assets,
authored values, structured events, Demo/Server behavior, permissions, task and
reward rules, ledger, backend and schema are unchanged. No migration or new
localization key. No N4 work.

The supplied N3.2 state was uncommitted. Delivery stages only the N3.3 delta,
including selected hunks in shared files; the earlier N3.2 and founder changes
remain in the working tree. Thus the N3.3 commit does not itself publish N3.2.

## Controls and content direction

Empty authored inputs/textareas inherit the current UI direction. Populated
controls use native `dir="auto"`; entering English in Persian UI starts LTR,
entering Persian/Arabic/Hebrew starts RTL, and clearing restores UI direction.
This also covers controls without placeholders, such as custom reward descriptions
and fulfillment notes. Placeholder strings and stored values are untouched.
Inputs, textareas, selects, their placeholders, and field labels use logical
`text-align:start`. Email values keep technical LTR direction with UI-directed
empty placeholders.

Audited controls: task title/description, task search/sort, all task action notes,
submission estimate/upload, handoff reason/owner search/priority/deadline/reward,
review notes, reward search/filters/category/name/description/cost/stock/dates/
quota/executor checkboxes, redemption cancellation/reference/fulfillment notes,
notification search, wallet selector, Admin adjustment/upload policy, login and
Test Lab authored issue fields. Range, number, date and select affordances remain
native; date segment order and native calendar behavior are not manually mirrored.
Checkbox labels follow their existing flex ordering. There are no custom
comboboxes, autocomplete, radio controls, prefix/suffix overlays or custom search
clear buttons in this baseline; segmented and choice buttons provide those
selection workflows.

## Widgets and physical-coordinate audit

| Occurrence | Classification and result |
| --- | --- |
| Test Lab `marginLeft:auto` | Semantic trailing metadata; changed to `marginInlineStart:auto`. |
| Segmented pill | Physical `offsetLeft` measurement must have a physical `left:0` anchor. Tracks X/Y/width/height, wrapped rows, font sizing, live locale/direction changes and resize. Resize/mutation observers are cleaned up. |
| Overview chart `grid.left/right:8` | Symmetric canvas plot bounds, not reading direction; retained. |
| Account popover, bell badge/popover, welcome dismiss, collapsed nav badges | Existing `inset-inline-start/end`; retained and checked in RTL. |
| Progress fill/ghost/value | Fill has logical inline start, ghost uses logical progress offsets, value uses full inset; preserve quantitative meaning. |
| Timeline rule/dots | Existing logical inset and inline padding; retained. |
| Sidebar/drawer | Existing logical edges and N3.1 directional animations; retained. Drawer title can wrap and close button cannot shrink. |
| Shadows, gradients, vertical offsets, centered modal bounds | Physical decoration/vertical geometry; retained. |
| Tables, toolbar, cards, tabs, modal footer, wizard steps | Existing logical alignment/flex direction/wrapping; verified instead of blindly replacing coordinates. |
| URL tokens | LTR bidi isolation on existing linkified URLs; text/href unchanged. |

No global right alignment, stored bidi controls, media mirroring, added fonts or
font package changes. Existing typography and spacing/radius/control-height
scales remain intact.

## Attachments and media

Image, video and file uploads use the existing attachment cards. The baseline
has no in-app image preview, video player or upload-progress UI: demo opening is
an explicitly labeled metadata preview; server opening retrieves authenticated
bytes for a native browser viewer/download. No new player or preview feature was
introduced.

Shared queue cards now use native buttons, keeping mouse and keyboard removal
available. Each card isolates the natural-direction filename and LTR size;
filename ellipsis can shrink while metadata/open/remove actions stay visible.
The full name remains in DOM/accessibility text and the tooltip. Submission and
Create Task/Handoff queues share this presentation; validation/upload/dispatch
behavior is unchanged. Stored attachment chips use the same bounded layout.
Confirmation chips retain wrapping/full text. Media bytes, native video controls
and image/video aspect ratios are unaffected.

Windows reserves port 4321. The override is in ignored `report/n33/playwright.config.ts`;
