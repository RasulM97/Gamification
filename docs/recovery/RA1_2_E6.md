# E6 — bounded production staging cleanup

Scope is a confirmed production error path, not test-harness cleanup.
Historical Stage 2 `stage2-20261020-c9c56df-7b31` is unchanged:

* The real mid-transfer process kill had confirmed death/quiescence and **zero
  surviving files or rows**. It is not evidence of a production orphan there.
* The labelled second-save filesystem exception left the first staged file
  orphaned because `stage_files` raised before entering `mutate`.
* Partial-write crash and staged-abandon cases were labelled simulations.
  They remain distinct from actual process-kill evidence.

New tests reproduced the second-save leak and an ordinary partial-write
exception directly against production code. Before the fix, all three new
cleanup/ownership assertions failed (run `e6-before-20261021`). The third check
injects a generated-name collision to prove cleanup must own a file before
deleting it; it is an ownership negative control, not a historical collision.

Production diff: only `routes.py` and `storage.py`, +35/-10 lines.
`stage_files` collects each successful save and cleans the collected files if a
later save fails. `LocalStorage.save` exclusively creates its generated name and
removes its own partially written file on an ordinary write/close exception.
It cannot overwrite or delete a pre-existing file on a name collision.
Best-effort cleanup attempts every owned file, logs deletion failures and retains
the original command/write error. Pre-commit and duplicate-delivery cleanup use
the same helper. **Unknown-commit bytes remain retained**, preserving F02's
committed-attachment protection.

Targeted verification: **10 passed** in `e6-after-20261021`, covering four E6
tests, five F02 outcome tests and one economic rollback test. The cleanup failure
test confirms the original error survives, later files are still cleaned, and
an undeletable file is logged rather than falsely reported as removed.

No temp/rename protocol, garbage collector, lifecycle redesign or deletion of
historical files was introduced. Abrupt process/OS termination cannot run Python
cleanup; staged-abandon/hard-crash orphans and retained unknown-commit files may
still require operator reconciliation. No claim of universal crash safety is
made. No harness/evidence rules were changed or rerun as a full suite.
