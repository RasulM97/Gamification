## Account synchronization root cause

N7's API client reads the shared localStorage token for every request, while each tab's React store keeps its own `me` and bootstrap state. Signing in to another account in a second tab can therefore send the first tab's actions with the second account's token. N7 lacks a storage-event session boundary and does not discard in-flight results when identity changes. The server correctly treats another recipient's notification as unavailable; refetch alone cannot repair stale `me` identity.

## Cancellation authority

Only the task creator (if still authorized management) or Admin may cancel a task. An owner cannot decide their own cancellation payout. Visibility or review delegation alone does not grant cancellation authority. This existing rule remains intact.
